## 五、本轮重点变更与修复

### 5.1 管理员安全（第一层）

| 项 | 内容 |
| --- | --- |
| 管理员白名单 | 新增 `admin_users` 集合；只有白名单微信显示/进入管理后台 |
| 首次初始化 | 无管理员时 `whoami` 返回 bootstrap，首位用口令登录的微信自动绑定为管理员 |
| 店员授权 | 「员工绑定」页可「设为管理员/取消管理员」，取消后立即清会话 |
| 登录限流 | `admin_attempts` 记录失败次数，连续 5 次锁定 10 分钟 |
| 会话绑定 | 所有管理云函数校验会话 openid = 调用者 openid，token 跨微信不可用 |
| 入口隐藏 | 个人页按 `whoami` 显示管理入口，普通员工/顾客不可见 |

### 5.2 到店交付流程

- 订单状态：下单（未收款）→ 接单/备餐 → 制作完成（可取餐通知）→ 员工到店核对 → **收款并交付（checkout）** → 完成；
- 未收款直接完成返回 `PAYMENT_REQUIRED`；已收款显示「已取餐/完成配送」；
- 待取餐允许取消并回补库存（爽约场景）；
- 配送单 checkout 完成时继续发「已送达提醒」。

### 5.3 其他修复

| 问题 | 处理 |
| --- | --- |
| 取消单在后台显示“待接”/仍显示收款 | 统一 cancelled→cancel 归一化；已取消不再显示收款 |
| 订单详情底部三个大按钮不自然/接单文字不居中 | 收款上移为待取餐提示卡，底部唯一主按钮 + 取消文字链；按钮 flex 居中 |
| 菜品删除后旧购物车下单报 SDK 错误 | 服务端返回 `DISH_NOT_FOUND` + 菜名；购物车自动移除失效条目 |
| 超时未付款无触发器时无法释放库存 | 管理端订单列表惰性清理 + `orderTimeout` 定时任务双重兜底 |
| 售罄第二天不恢复 | `soldOutDate` 按东八区自然日自动失效；定时清理可选 |
| 管理端订单列表会话失效/空白 | 进入时服务端校验会话自动跳登录、错误可重试、列表查近 30 天、诊断日志 |
| 手动刷新无反馈 | 刷新中 loading + 文案变「刷新中…」+ 成功 Toast + 更新时间 |

## 六、安全与合规

- **敏感信息**：源码/配置/文档扫描 0 命中（明文口令、GitHub token、私钥、AK/SK、AppSecret）；公开仓库不包含管理口令。
- **管理员身份**：`admin_users` 白名单 + 会话 openid 绑定 + 登录限流；普通用户看不到入口，非白名单微信即使知道口令也不能登录。
- **密钥存储**：管理密码 scrypt 加盐哈希存 `admin_config`；token 使用 `crypto.randomBytes`；12h TTL。
- **数据库权限**：注意云开发控制台**没有“仅云函数可读写”预设**；管理集合选「所有用户不可读写」，菜单/配置/促销选「所有用户可读」，云函数不受客户端规则限制。
- **权限最小化**：仅订阅相关云函数申请 `subscribeMessage.send/getTemplateList`。
- **忽略文件**：`project.private.config.json`、`.cloudbase/`、`node_modules/`、日志/临时文件均已忽略。
- **上线必配**：`adminLogin` 环境变量 `ADMIN_PWD`；公众平台隐私保护指引（相册）；首次登录后立即绑定店主微信并清理旧 `admin_sessions`。
