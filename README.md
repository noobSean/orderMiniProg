# 企业内网点单小程序

企业内部单店点单微信小程序：**最低开发与部署成本**方案，使用**微信原生小程序 + 微信云开发（CloudBase）**，零服务器、免域名备案，按量计费（500–1000 DAU 月成本通常 ≤ 几十元，常在免费/基础额度内）。

- 支持两种模式：**到店自取**（凭取餐号取餐）与**配送**（送到部门/楼栋/工位）
- 支付方式：**现场刷员工卡结算**（本程序不接在线收款，无商户号/营业执照要求）
- 内置**管理端**：菜单管理、订单处理、门店配置、营业统计
- 员工首次进入绑定工号，与微信 openid 关联；**已绑定员工清缓存 / 换设备后自动恢复登录**，无需重新绑定

## 一、准备工作（一次性）

1. **注册小程序**：在 [微信公众平台](https://mp.weixin.qq.com) 注册小程序。
   - 企业内部使用、不收款、无需推送：可用**个人主体**（免费）即可体验整套流程。
   - 若需要**订阅消息**（接单/可取餐推送）或后续上支付，需**企业主体并完成认证**（300 元/年）。MVP 阶段可先不做。
2. 下载**微信开发者工具**：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
3. 获取小程序 **AppID**，填入 `project.config.json` 的 `appid` 字段（替换 `touristappid`）。

## 二、开通云开发并建环境

1. 在**微信开发者工具**中导入本工程根目录（`order_recipe_miniprog`）。
2. 点击工具栏「云开发」→ 开通 → 创建环境（如 `order-recipe-xxxx`），记下**环境 ID**。
3. 打开 `miniprogram/config/index.js`，把环境 ID 填入 `envId`：
   ```js
   module.exports = {
     envId: 'your-env-id'    // ← 填你创建的环境 ID
   };
   ```

> 管理口令**不保存在小程序端、也不写进代码仓库**，支持两种来源（数据库优先）：
> 1. **数据库** `admin_config/admin_pwd`：管理后台「修改密码」后写入（scrypt 加盐哈希，不存明文）；
> 2. **云函数环境变量** `ADMIN_PWD`：首次部署的初始化口令，只有数据库没有记录时生效。
>
> 首次使用：先在云函数 `adminLogin` 配置环境变量 `ADMIN_PWD`，登录管理后台后在「修改密码」里改成自己的强密码（改完环境变量不再参与校验，所有设备需重新登录）。忘记密码：在云开发控制台删除 `admin_config` 集合中的 `admin_pwd` 记录，即可重新用环境变量口令登录/重置。
>
> **FAQ：修改密码后，云函数环境变量 `ADMIN_PWD` 为什么没变？**
> 这是正常的。环境变量属于「部署配置」，云函数运行时**不能修改自己的环境变量**，所以「修改密码」不会去改它；新密码以 **scrypt 哈希**写入数据库 `admin_config/admin_pwd`，登录时**数据库优先**，环境变量旧值不影响新密码登录，仅作为初始化/重置口令保留。若确实要同步环境变量，只能在云开发控制台手动修改（保存后函数实例会自动重启）；也可以保持不动。

> **UI 注意**：微信基础组件在 `style: "v2"` 下会给 `button` 注入固定宽度（184px）和 auto 外边距，容易把同行文字挤没或让按钮溢出。`miniprogram/app.wxss` 里已统一重置（`button { width: auto !important; ... }`）；新增按钮样式如需固定宽度，请在自己的类里用 `width: ... !important` 显式覆盖。

## 七、图片等静态资源上传（云存储）

菜品图片、门店 Logo、活动横幅等静态资源统一使用**微信云存储**（开通云开发即自带，无需额外购买）。

### 7.1 云存储权限（重要）

云开发控制台 →「存储」→ 权限设置，保持默认 **「所有用户可读，仅创建者可写」**。

- 员工端需要读取菜品图（所有用户可读）；
- 管理端登录后才能上传（仅创建者可写，上传者即管理员微信）；
- **不要**改成「仅创建者可读写」，否则其他员工看不到菜品图。

### 7.2 管理端上传菜品图（已内置）

1. 管理后台 →「菜单管理」→ 新增/编辑菜品 →「图片」区块 →「＋ 选择图片」；
2. 选图后自动压缩并上传到云存储 `dishes/<时间戳>-<随机>.jpg`，显示上传进度；
3. 保存菜品时把云文件 ID（`cloud://...`）写入 `dishes.image`；员工端点餐页、管理端菜单列表会自动显示缩略图；
4. 「更换」会替换图片；「×」删除图片；保存成功后会自动清理被替换掉的旧云文件，避免堆积。

> 说明：上传是**客户端直传**（`wx.cloud.uploadFile`），不经过云函数（云函数请求体有大小限制，不适合传图片）；安全由云存储权限 + 管理端登录态共同控制。

### 7.3 其他静态资源复用

其他页面（如以后要加门店 Logo、首页横幅、公告图）直接复用 [miniprogram/utils/upload.js](miniprogram/utils/upload.js) 即可：

```js
const upload = require('../../utils/upload');

// 选择并上传（自动压缩），dir 为云存储目录前缀；用户取消返回 ''
const fileID = await upload.pickImage({ dir: 'banners', onProgress: p => console.log(p + '%') });

// 存库：把 fileID 写进对应集合字段即可，<image src="{{fileID}}"> 可直接显示

// 预览：云文件 ID 需要先换临时 https 链接
const url = await upload.tempUrl(fileID);
wx.previewImage({ urls: [url] });

// 删除（非 cloud:// 文件会自动忽略）
await upload.remove(fileID);
```

常用目录约定：`dishes/`（菜品图）、`logo/`（门店 Logo）、`banners/`（横幅）、`misc/`（其它）。

## 八、员工端登录与恢复登录（无账号密码）

员工端没有账号密码：**身份就是微信 openid**，首次「绑定工号」后档案存在 `employees` 集合（按 openid 关联）。

- **启动自动登录**：小程序启动时调用 `login` 云函数，用当前 openid 查员工档案；查到即自动恢复登录（本地缓存被清、卸载重装、换网络都不需要重新绑定），查不到才显示「去绑定」。
- **退出登录**：我的 →「退出登录」会清空本地档案并记住退出状态；下次启动**不会**自动登录，页面显示「已退出登录 / 重新登录」，点「重新登录」即可恢复。
- **恢复入口**：绑定页底部也有「已绑定过？用当前微信直接登录」，适合登录态丢失但误入绑定页的情况。
- **资料同步**：回到前台 / 下拉刷新「我的」时会在后台向云端刷新档案；管理员改名或解绑后，员工端会同步（被解绑则回到「尚未绑定」）。
- **安全**：`login` 云函数只按调用者自己的 openid 返回档案，不能查询他人；管理端鉴权仍走独立的 `admin_sessions` 会话。

相关代码：`miniprogram/app.js`（ensureLogin / loginNow / logout / refreshProfile）、`pages/profile/profile.js`、`pages/bind/bind.js`、`cloudfunctions/login/index.js`。

## 九、微信订阅消息（下单成功 / 可取餐 / 已送达提醒）

三类通知已接入，全部使用小程序**订阅消息**（微信「服务通知」），通过云开发**云调用**下发，不需要服务器、域名或公众号。

| 通知 | 触发时机 | 适用订单 | 小程序端配置键（config） | 云函数模板常量 / 环境变量 |
| --- | --- | --- | --- | --- |
| 下单成功通知 | 下单成功后立即 | 自取 + 配送 | `orderPlaced` | `submitOrder` → `ORDER_PLACED_TEMPLATE_ID` |
| 可取餐提醒 | 状态变为 `ready`（管理端点「制作完成」） | 自取 | `pickupReady` | `orderAdmin` → `PICKUP_READY_TEMPLATE_ID` |
| 已送达提醒 | 状态变为 `done`（管理端点「完成」） | 配送 | `deliveryDone` | `orderAdmin` → `DELIVERY_DONE_TEMPLATE_ID` |

### 9.1 能力与限制（先了解）

- 采用**一次性订阅消息**：用户在下单弹窗点「允许」一次，系统才能下发一条；一次弹窗可同时请求「下单成功 + 取餐/送达」两个模板（各消耗各自额度）。
- 用户可在弹窗勾选「总是保持以上选择，不再询问」，后续不再弹窗（可在小程序设置里修改）。
- **长期订阅**只对特定服务类目（医疗/政务/交通等）开放，企业内部餐饮类目一般只能用一次性订阅。
- 用户没授权/拒绝 → 下发失败（服务端日志返回 43101），**不影响订单和状态流转**。
- 开发调试可用云函数环境变量 `SUBSCRIBE_MINIPROGRAM_STATE=developer`（开发版）或 `trial`（体验版）；正式发布后用 `formal`。

### 9.2 开通步骤（一次性配置）

1. 登录 [微信公众平台](https://mp.weixin.qq.com) →「功能」→「订阅消息」→ 开通；
2. 分别选用/申请三个模板（没有合适的可在模板库申请新模板）：
   - 下单成功通知（如「订单提交成功」「下单成功提醒」）
   - 取餐提醒（如「取餐提醒」「餐品可取通知」）
   - 配送完成/送达通知（如「配送完成通知」「订单完成提醒」）
3. 复制三个模板的 **模板 ID**（公众平台模板列表里可直接复制）；
4. 填 **小程序端** `miniprogram/config/index.js` 的 `subscribeTemplates` 三项；
5. **云函数端不用重复填模板 ID（可选）**：小程序端调用时会自动把 `subscribeTemplates` 随请求传给云函数，云函数直接使用；
   - 如需按环境区分，仍可在云函数环境变量覆盖：`ORDER_PLACED_TEMPLATE_ID`、`PICKUP_READY_TEMPLATE_ID`、`DELIVERY_DONE_TEMPLATE_ID`；
   - 两端必须使用同一个模板，否则授权与下发不是同一个模板，会报 43101。
6. **字段映射已自动化，一般不需要改代码**：
   - 云函数会调用 `subscribeMessage.getTemplateList` 读取你账号下的模板，解析模板内容（如「取餐号:{{character_string1.DATA}}」）并按**中文标签**自动匹配字段：取餐号、订单号、**商品名/餐品名称**、**餐品数量**、**餐品详情/订单内容**、**配送时间**、**送达/下单时间**、**备注**、金额、地址、门店、提示、姓名；
   - 不同模板的关键字名/顺序不同也没关系（thing1/character_string2 顺序换了、编号不同都能自动识别）；
   - 部署后可在云函数日志核对解析结果：`[subscribe] template loaded ... keywords:["character_string1(取餐号)",...]`；
   - 若模板标签特殊导致识别不全：修改对应云函数 `index.js` 内联的 `createSubscribe`/`pickRole()` 规则，或调整该函数里的 `*_FALLBACK_MAP`（角色→关键字）兜底映射；把模板内容发我也可以直接帮你改好。
7. 重新上传部署 **三个**云函数（都选「上传并部署：云端安装依赖」）：
   - `submitOrder`、`orderAdmin`（通知逻辑已**内联进 index.js**，不再依赖额外文件；上传目录即可）
   - `subscribeCheck`（新增，自检工具，见 9.6）
   > 三个目录的 `config.json` 都已声明云调用权限 `subscribeMessage.send` + `subscribeMessage.getTemplateList`；权限更新约 10 分钟缓存，提示 -604101 时稍等再试。

### 9.3 触发与调试

- **下单**：点「提交订单」时一次弹窗请求 [下单成功通知 + 自取可取餐 / 配送已送达] 两个模板 → 下单成功后立即发「下单成功通知」；
- **自取**：管理端订单详情点「制作完成」（`making → ready`）→ 发「可取餐提醒」；
- **配送**：管理端订单详情点「完成」（`ready → done`）→ 发「已送达提醒」；
- 点击通知卡片可直接打开对应订单详情页；
- 云函数日志可看到完整过程：`[subscribe] template loaded ...`（识别到的字段）、`[subscribe] sent ...`（成功）、`[subscribe] send failed ... 43101`（用户未授权）等；
- 若日志出现 `getTemplateList failed ... -604101`，说明云调用权限还没生效，此时会退回 `*_FALLBACK_MAP` 兜底映射；等权限生效（约 10 分钟）后重新测试即可；
- 调试建议：先用 `SUBSCRIBE_MINIPROGRAM_STATE=developer` + 开发者微信测；一次性订阅每次授权只够一条，重复测试需要重新下单。

### 9.4 模板字段长度限制（常见报错 47003）

| 关键字类型 | 限制 |
| --- | --- |
| `thing` | 20 个以内字符 |
| `character_string` | 32 位以内数字/字母/符号 |
| `amount` | 1 个币种符号 + 10 位以内数字 |
| `time` | 24 小时制时间，如 `2026-10-29 15:23` |
| `date` | 年月日，可带时间 |
| `phrase` | 5 个以内汉字 |
| `name` | 10 个以内汉字 |

**餐品相关字段的取值规则**（自动按模板标签识别）：

| 模板关键字标签 | 取值 | 示例 |
| --- | --- | --- |
| 商品名 / 餐品名称 / 菜品名称 | 去重后的菜名，顿号分隔 | 黑椒牛柳饭、鲜榨橙汁 |
| 餐品数量 / 份数 | 总份数（纯数字，适配 number 类型） | 3 |
| 餐品详情 / 明细 / 内容 | 菜名(规格)+加料×数量；若是 `thing`（最多20字）会自动改用精简版「菜名×数量」 | 黑椒牛柳饭×1、鲜榨橙汁×2 |

> - `thing` 类型最多 20 字：餐品详情太长时会自动降级为「菜名×数量」的精简版，避免被截断成半截；
> - `character_string` 只能填数字/字母/符号，**不能放中文菜名**；模板里的「商品名」建议选择 `thing` 类型关键字；
> - `number` 类型只能填纯数字，餐品数量已按纯数字输出（如 `3`）。

**当前项目使用的三套模板与自动映射结果**：

| 模板 | 关键词 | 自动映射到的数据 |
| --- | --- | --- |
| 取餐提醒 | 取餐号码 | 取餐号（如 `18`） |
| | 餐品详情 | 菜名(规格)+加料×数量；thing 超 20 字自动精简为「菜名×数量」 |

| | 商品名 | 去重菜名，顿号分隔（如 `黑椒牛柳饭、鲜榨橙汁`） |
| 下单成功通知 | 订单内容 | 同「餐品详情」（thing 自动精简） |
| | 下单时间 | 下单时间 `yyyy-MM-dd HH:mm` |

| 43101 | 用户未订阅 / 一次性额度已用完 | 正常现象，让用户下次下单重新授权 |
| 40037 | 模板 ID 不正确 | 检查两端模板 ID 是否一致、是否填错 |
| 47003 | 参数错误（字段类型/长度不符） | 按模板关键字改字段名，检查长度 |
| 43107 | 订阅消息能力被封禁 | 检查模板/小程序是否被限制 |

### 9.6 自检工具（推荐先用它排查）

管理后台 →「门店配置」→ 最下方「通知自检」：

- **检查通知配置**：一次性检查三类模板——是否配置了模板 ID、该 ID 是否在当前小程序账号下、解析出的关键字/字段映射是否正确、云调用权限是否正常；
- **测试·下单成功 / 测试·可取餐 / 测试·已送达**：会先弹微信订阅授权，允许后立即给当前微信发一条测试通知，并显示发送结果（含错误码）。

常见“收不到通知”的原因对照：

| 自检显示 | 原因 | 处理 |
| --- | --- | --- |
| ❌ 未配置模板 ID | 小程序端 `config.subscribeTemplates` 没填 | 填模板 ID 后重新编译 |
| ❌ 模板 ID 不在当前账号下 | 模板 ID 填错，或模板没添加到账号 | 到公众平台复制正确模板 ID |
| ⚠️ 拉取模板列表失败（-604101 等） | 云函数没部署/云调用权限未生效 | 重新上传部署 `subscribeCheck`，等约 10 分钟 |
| 发送失败 43101 | 用户没授权/额度已用完 | 测试时先点「允许」；每次授权只能发一条 |
| 发送失败 47003 | 模板字段类型/长度不符 | 检查模板关键字，必要时改 `index.js` 内联的匹配规则/兜底映射 |
| 发送成功但没收到 | 微信通知被免打扰/关闭 | 检查微信「服务通知」设置、手机通知权限 |

> 云函数日志里也会打印每次下发过程（`[subscribe] template loaded / sent / send failed`），可配合自检排查。

### 9.7 部署与 443 错误排查

云函数调用返回 `status_code: 443` / `ret_code: -1`（常见底层是 `145 code exit unexpected`，duration 0ms），表示**函数进程启动失败、代码根本没执行**，不是业务逻辑报错。常见原因与处理：

| 可能原因 | 处理 |
| --- | --- |
| 部署不完整（例如只更新了 `index.js`，漏传新增的公共文件） | 订阅消息逻辑已**内联进 `index.js`**，不再依赖额外文件；右键云函数目录 →「上传并部署：云端安装依赖」重新上传 |
| 代码语法/依赖问题（本地能跑、云端 Node 版本不兼容） | 重新上传并查看部署提示；云函数控制台「测试」传 `{"action":"ping"}`，能返回 `pong` 才说明启动正常 |
| 函数处于部署中/版本异常 | 重新部署，或删除后重新创建函数再上传 |
| 权限配置文件 `config.json` 校验失败导致部署异常 | 确认 `config.json` 是合法 JSON（本项目已提供），重新上传 |

**部署后自测顺序**：
1. 云开发控制台 → 云函数 → `submitOrder` →「测试」→ 参数 `{"action":"ping"}` → 应返回 `{"ok":true,"data":{"pong":true,...}}`；
2. `orderAdmin` 同样 ping 一次；
3. 再走真实下单/接单流程，日志里搜索 `[subscribe]`；
4. 最后用管理后台「门店配置 → 通知自检」逐项测试。

> `subscribeCheck` 是独立的云函数，部署它不影响 `submitOrder`。

> **注意：`{"action":"ping"}` 只内置在 `submitOrder` 和 `orderAdmin` 两个函数**（用于部署自检）。
> 如果你在其它云函数（如 `adminLogin`、`subscribeCheck`、`settingsAdmin`、`dishAdmin` 等）里测试，会返回 `{"ok":false,"message":"未知 action: ping"}`——这是该函数不认识这个 action，属正常现象，**不代表部署失败**。
> 若在 `submitOrder` / `orderAdmin` 里测试仍返回「未知 action: ping」，说明云端还是旧版本代码：重新「上传并部署：云端安装依赖」该函数目录，确认控制台代码里包含 `action === 'ping'`，再测应返回：
> ```json
> {"ok":true,"data":{"pong":true,"fn":"orderAdmin","version":"notify-inline-v1","now":"..."}}
> ```

### 促销 / 折扣（proto）

当前实现的是「折扣活动」最小闭环，数据集合 `promotions`，管理后台「促销活动」维护：

| 字段 | 说明 |
| --- | --- |
| `name` | 活动名称（≤20 字） |
| `scopeType` | `all` 全部品类 / `category` 指定分类 / `dish` 指定菜品 |
| `categoryIds` / `dishIds` | 指定范围时的分类/菜品 `_id` 列表 |
| `discount` / `rate` | 折扣（如 8.5 表示 8.5 折）/ 折扣率（0.85） |
| `startAt` / `endAt` | 活动起止时间（毫秒时间戳，可空 = 不限） |
| `enabled` | 是否启用 |

**规则（proto 版，简单可预期）**：

- 同一菜品同时命中多个活动时，只取**折扣力度最大**的一个，**不叠加**；
- 折扣作用于「菜品单价（含规格/加料）× 数量」，金额按分四舍五入；
- 服务端 `submitOrder` 会**重新计算**并快照落库：订单记录 `originalTotal`、`discountAmount`、`discounts`，明细记录 `originalPrice`、`discountRate`、`discountAmount`、`lineTotal`、`promotionName`；
- 客户端菜单/购物车展示的活动价与优惠仅为**预估**（同一套规则），最终金额以服务端下单结果为准；
- 已下单订单的优惠是快照，之后修改/停用活动不影响历史订单。

**部署/配置**：

1. 新建云函数 `promoAdmin`（右键「上传并部署：云端安装依赖」）；
2. 云数据库新建集合 `promotions`：权限「所有用户可读，仅云函数可写」（员工端菜单/购物车需要读活动；写入只走管理端云函数）；
3. 重新部署 `submitOrder`（折扣计算在服务端）；
4. 重新编译小程序（菜单/购物车展示、管理端促销页面）。

**后续可扩展**（proto 稳定后按需求迭代）：满减/满赠、第二份半价、优惠券/兑换码、会员价、活动叠加/互斥规则、限购、活动统计、按人群/时段、活动审批与定时预热等。

### P0：线下收款、取餐核销与超时释放

本项目不接在线支付，员工在 POS 用员工卡付款，因此增加「支付状态」与「取餐核销」：

| 字段 | 说明 |
| --- | --- |
| `paymentStatus` | `unpaid`（新订单默认）/ `paid`；历史订单无此字段按已收款处理 |
| `paidAt` | 店员点「收款」的时间 |
| `pickedUpAt` | 自取订单点「已取餐」的时间（用于对账） |
| `cancelReason` | `unpaid_timeout` 表示超时未付款被自动取消 |

**流程**：员工下单（待收款）→ 到店报取餐号，POS 刷员工卡付款 → 店员在管理端「订单」点「收款」→ 制作完成（可取餐通知）→ 员工取餐，店员点「已取餐」。

**定时任务**：新增云函数 `orderTimeout`（`config.json` 内置两个 timer 触发器）：

- `unpaidTimeout`：每 5 分钟扫描一次，把「pending 且 unpaid 且超过 15 分钟」的订单取消并回补库存；可用环境变量 `UNPAID_TIMEOUT_MIN` 调整分钟数；
- `dailySoldOutReset`：每天 04:00 清除菜品的「快捷售罄」标记（**可选**：售罄标记本身按东八区自然日自动失效，第二天无需触发器也会恢复在售）。

**部署**：

1. 上传部署 `orderTimeout`（右键「上传并部署：云端安装依赖」），部署后在云开发控制台确认「定时触发器」里出现两个触发器；若没有，请手动新增；
2. 重新部署 `submitOrder`（售罄拦截 + 新订单 paymentStatus）与 `orderAdmin`（收款/取餐核销）；
3. 重新编译小程序（管理端收款按钮、售罄开关、员工端支付提示、订单页自动刷新）；
4. 触发器按云函数所在时区执行，若发现 04:00 重置时间不符，可在控制台调整 cron。

> 管理端「订单」页现在每 15 秒自动刷新，发现新订单会震动 + Toast 提示（小程序在前台时有效）。

#### 如何新增 orderTimeout 的定时触发器

**注意**：云开发控制台函数详情里的「定时触发器」面板只有「刷新」和列表，**没有“新建”按钮**（截图里的「暂无数据」是正常的）；创建入口在开发者工具的文件树右键菜单，优先尝试：

1. 在开发者工具左侧文件树，**右键 `cloudfunctions/orderTimeout` 目录**，看菜单里有没有 **「上传触发器」**：
   - 有 → 点它（`config.json` 已内置两个触发器），然后到云开发控制台「云函数 → 定时触发器」确认；
2. 如果没有「上传触发器」菜单，再到云开发控制台手动添加：
   - 开发者工具顶部「云开发」→ 左侧「云函数」→ 找到 `orderTimeout` → 函数详情页的「触发器 / 函数配置」标签，或左侧「定时触发器」菜单；
3. 新建两个 **定时触发器**：

| 名称 | Cron（7 位：秒 分 时 日 月 周 年） | 说明 |
| --- | --- | --- |
| `unpaidTimeout` | `0 */5 * * * * *` | 每 5 分钟检查超时未付款订单 |
| `dailySoldOutReset` | `0 0 4 * * * *` | 每天 04:00 清除售罄标记 |

4. 保存后确认触发器列表中出现这两条；触发器只在**云端**生效，开发者工具本地「测试」不会自动定时。

**临时手动执行**（触发器没配好时可以先这样验证）：云函数控制台 → `orderTimeout` →「测试」：

| 测试参数 | 作用 |
| --- | --- |
| `{"action":"ping"}` | 部署自检，返回 pong |
| `{}` | 立即执行一次「超时未付款」检查 |
| `{"action":"dailySoldOutReset"}` | 立即清理所有售罄标记 |

> Cron 时区以云环境为准（通常为东八区）；若 04:00 重置时间不对，按控制台提示调整。

> **现在定时触发器完全可选**：
> 1. 超时未付款：管理端「订单」页每次刷新（含 15 秒轮询）会顺手清理并回补库存，只要店长/店员开着订单页就会生效；
> 2. 售罄标记：按东八区自然日自动失效，第二天不用触发器也会恢复在售；
> 3. 配触发器只是让“没人打开后台时”也能自动清理超时订单，配不好不影响营业。


#### 管理端「订单处理」空白 / 刷不出数据怎么办？

1. **先重新登录管理后台**：管理会话 12 小时过期，或修改密码后所有旧会话失效；新版页面检测到服务端会话失效会自动跳登录页。
2. 看云函数 **orderAdmin 日志**：搜索 `[orderAdmin] list`，会打印 status/count/autoCancelled；count=0 说明查询没匹配到数据。
3. 检查云开发数据库 orders：集合里是否有订单、createdAt 是否为日期类型；管理端现在默认查最近 **30 天**（最多 100 条），更早订单不会显示。
4. 核对小程序 envId 与云函数所在环境是否一致（多环境容易看错）。
5. 页面加载失败现在会显示错误原因和「重新加载」按钮；仍空白请把 orderAdmin 日志发我。

#### 提交订单提示 `document.get:fail ... does not exist` 怎么办？

表示购物车里的某个菜品在数据库里已经不存在（通常是**菜品被删除/重建后 ID 变了，购物车里还留着旧 ID**，或开发者工具本地缓存了旧菜单）。

- 已优化：服务端会返回「菜品不存在或已删除（菜名），请刷新菜单后重试」并携带 `DISH_NOT_FOUND` + `dishId`；
- 员工端购物车收到该错误会**自动移除这条失效菜品**并弹窗提示，重新加购即可；
- 也可以在「我的」或开发者工具里清缓存，重新进入点餐页刷新菜单。
